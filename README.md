# lmteavm

A browser application skeleton combining TeaVM-compiled Java with annotation-dispatched LMCode entries and typed host functions. The example includes JSON todos, SVG, 2D canvas, WebGL, animation, hydration, and data-driven drawing.

## Build

Requirements: Java 21, Maven, Node 24.15 or newer, and `lmscript` from `@lmctl-ai/lmctl` 0.2.482 or newer. Install `lmcode-java` 0.1.1 into the local Maven repository.

```sh
git clone https://github.com/lmctl-ai/lmcode-java.git
mvn -f lmcode-java/pom.xml -DskipTests install
npm install --prefix compiler @lmctl-ai/lmctl@0.2.482
export PATH="$PWD/compiler/node_modules/.bin:$PATH"
export LMCODE_COMPILER_MODULE="$PWD/compiler/node_modules/@lmctl-ai/lmctl/dist/dsl.js"
mvn clean package
```

The site is generated under `target/demo/`. The build uses the exported LMScript compiler API from `LMCODE_COMPILER_MODULE`. Override `demo.output` to write directly into another site:

```sh
mvn -Ddemo.output=/absolute/site/path clean package
```

## Integration tests

```sh
npm ci
npx playwright install --with-deps chromium
npm test
```

The test starts a local static server, launches Chromium, and verifies all seven modes, WebGL pixels, animation frames and controls, JSON requests, hydration, clipboard behavior, and browser errors. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to use an existing Chromium binary.

GitHub Actions runs the same build and integration test on Ubuntu with public dependencies only.

## Application recipe

1. Define host functions and interfaces in `src/main/lmcode/todo-handler.schema.json`.
2. Implement annotation-dispatched entries in `src/main/lmcode/todo-handler.lms`.
3. Register matching Java callbacks through `Registry.function` in `BrowserDom.java`.
4. Load the generated bytecode and schema with `Program.load` in `DemoHandlers.java`.
5. Resolve entries by annotation and invoke them with `Program.call`.
6. Attach DOM events in Java; TeaVM compiles them to JavaScript.
7. Run the browser integration test after changing either side of the schema contract.

`DemoHandler` is a no-argument void entry interface. `TodoHandler` renders a todo label. `DrawCommand` receives one normalized JSON draw command. Both JSON drawing options use the same `@data` and `@draw` entries and differ only in their JSON file.

## JSON draw DSL

A document has a title and a command array. Commands are `rect`, `line`, `circle`, and `text`; all use `x`, `y`, and `color`. Rectangles use `w`/`h` for size, lines use them for the end point, and circles use `w` for radius. Text commands add `text`. Missing numeric fields default to zero and missing strings to empty values.
